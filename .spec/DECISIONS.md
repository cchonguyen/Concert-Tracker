# Architecture Decision Records (ADRs)

- **ADR-001 (2026-10-26):** Adopted the claude-harness-hub v2.0 harness (hooks, subagents, `.spec/` state). Engine files are copied unchanged from the hub so `/sync-harness` can update them; project rules stay in AGENTS.md and take precedence over the harness rules. `.spec/` files link to REQUIREMENTS.md and ARCHITECTURE.md rather than duplicating them. Rejected: replacing CLAUDE.md with the hub template (would drop the pointers to the project rules); copying the hub's `.spec/` files verbatim (they describe the hub, not this app).
- **ADR-002 (2026-10-28):** Manage section moves artists, people, venues, places, series and organizations to entity records with UUIDs. The Gemini audit returned APPROVED_WITH_REVISIONS, and all five blocking findings were checked against the code and applied to SYSTEM_SPEC.md section 3: kind-scoped alias uniqueness; `merged_into_id` with flattening, no hard delete and link constraints in both stores; dual-write of legacy text columns on rename, merge and venue → place during the 0014 release; reverse-patch manifests in `entity_history`; and venue provenance plus fillPatch-only list import. Its MVP "Do NOT Build" additions were taken as-is (no labels, single-name people, no delete), and its slice split was adopted as M1a–M6. Corrections to the verdict: tests run on Node's test runner (`npm test`), not vitest. `[UI / VISUAL]` slices still run `npm test` per AGENTS.md. `editPatch` exists only for rows from the app's own export or sheet (`src/services/listImport.ts`), so retiring it removes the read-back half of sheet sync, which matches Charlie's 2026-10-28 call that the app is the only source of truth. Already covered before the audit: one-way Sheets and CSV, and conflicts staying empty with a Data health ask.
- **ADR-003 (2026-11-13):** AI reader behind one provider-neutral interface, spec in docs/archive/ai-reader-spec.md. (1) Two adapters (Gemini paid, model pinned by name; Workers AI via the `ai` binding), chosen by `READER_PROVIDER`, default `gemini`, no automatic fallback. Rejected: a fallback chain (breaks AGENTS.md quota rule) and a third provider before the test. (2) Spend guards and the circuit breaker keep their counters in `quota_ledger` keys, not in `ai_calls`, so a missing log table can neither block nor unblock calls, and every Worker instance shares them. Rejected: summing `ai_calls` per check (extra subrequests, couples safety to the log). (3) The log is one insert per call and stores counts only, never page text. (4) Over-size input is refused and logged, not chunked, in v1; the existing declared `lineupWindow` stays. (5) SUPERSEDED by ADR-004: the recall test was an owner-only route doing one provider and one page per request; it is now a local CLI script. (6) Invalid JSON is a failed read that drops the page with a log line; no repair call and no retry.
- **ADR-004 (2026-11-13):** Revisions to ADR-003 from Charlie's audit (2026-11-12), applied to docs/archive/ai-reader-spec.md. (1) The recall test is a local CLI (`scripts/recall-test.ts`) over pure scoring in `src/server/reader/recall.ts`; no recall routes, no `run_id`, `names_expected` or `names_matched` columns, no `recall_test` feature, no `listAiCallsByRun` or `listRecallCandidates`, no React runner. The owner panel is observability only. Workers AI production slices (10.15, 10.16) are built only after Charlie reads the CLI result. Reason: a one-off evaluation does not earn permanent production surface. (2) Reasoning and parameters: `READER_THINKING_LEVEL` (default `LOW`); `thinkingBudget: 0` for `gemini-2.5*`, `thinkingLevel` for every other model; no sampling parameters; no trailing `model` turn; Workers AI `reasoning_effort` and `enable_thinking: false`; the empty-balance 402 or 429 maps to a 6 hour quota park. Reason: thinking tokens bill as output and can exhaust the output cap before JSON appears, and legacy parameters return 400. (3) Zero-deploy swaps: the unknown-price guard is removed; `FALLBACK_PRICES` (gemini 1.50/7.50, workers-ai 0.10/0.40 per million tokens) price unlisted models; only `-latest` aliases are refused, and only when `READER_PROVIDER` is explicit. (4) Breaker scope: guard 5 (input size) returns `input_too_large` for that page and guard 6 (job cap) parks only its job; neither touches `reader:breaker`. The breaker opens only on consecutive provider failures, provider 402/429, and guards 7 to 9. Reason: one big page must not stop every job. (5) Spend math: a pre-call in-memory check of `used + worstCase`, no ledger write before the call, one post-call write of the real cost. Reason: avoids double counting. The race note applies to non-queue callers only. (6) Defaults `READER_WINDOW_CHARS` 180000 and `READER_MAX_INPUT_CHARS` 200000 so a 43,000-token page is read whole; worst case per call is about $0.16 at the fallback price. (7) Model decision (Charlie): Gemini Hydrogen (`gemini-4-hydrogen`) is the wanted model, set only after the implementer confirms the id from the live model list and records the real price (slice 10.17); until then the code default stays `gemini-3.5-flash-lite`.
- **ADR-005 (2026-11-15):** Global Archive Merging, 4-tier Series/Brand Hierarchy, Multi-Weekend Pre-Fill, and Egress Cuts.
  (1) Nullable `event_editions.series_slug` (`ON DELETE SET NULL`) with removal of automatic stub `event_series` row creation for standalone concerts; standalone editions remain unattached to series.
  (2) 4-tier hierarchy `Brand -> Series -> Edition -> Event/Weekend`: add `brand` (text) and `aliases` (text[]) to `event_series`, `weekends` (`jsonb` array of `{ weekendNumber, name, startDate, endDate, ticketTypes?, lineupActs? }`) and `region` (text) to `event_editions`. Personal logged events link to edition + optional weekend index.
  (3) Option 3B fast-Enter auto-linking: typing an event line and pressing Enter directly auto-links if and only if exactly 1 verified series edition unambiguously matches without date/venue conflict; if 2+ editions match (e.g., multi-weekend or multi-city), auto-linking is suppressed and they are surfaced as 1-tap canonical candidates with a "None of these — search web / keep mine" escape hatch.
  (4) Supabase egress optimization: replace unbounded `event_editions` + `performances` payload scans with `getEditionHeaders` / `listEditionHeaders` (id, title, series_slug, dates, venue, city, region, act_count only) for `match.ts` and `dedupeProvisional.ts`; introduce `edition_lineup_facts` SQL RPC for single-roundtrip lineup retrieval; debounce Global Archive and edition suggestion client searches to >=300ms.
- **ADR-006 (2026-11-15):** Series Place & Tour Kind, Automatic Type Inheritance, and Multi-Weekend Autofill/Research.
  (1) `event_series.kind`: `'festival' | 'tour'` (not null, default `'festival'`). Festival series hold home `city`, `region`, and `country` at whatever granularity applies (`Las Vegas, NV, US` or regional `CA, US` with `city: null`). Missing place fields on attached editions resolve on read from the series (`Edition ?? Series`); edition-level values always take precedence when set. Tour series are location-agnostic (`city`, `region`, `country` null and disabled in UI/API); individual tour stops carry their own venue, city, region, country, and dates on `event_editions`.
  (2) Automatic Type (`Festival` / `Concert`) Inheritance (`R3.5`, `scale.ts`): `logged_events.kind` strictly stores only explicit user choice. Read-time `resolveEvent` passes the linked series's `kind` (`festival` -> `'festival'`, `tour` -> `'concert'`) as a read-only `seriesKind` signal into `eventScale()`, carried via the existing `event_series` join in `EDITION_HEADER_COLUMNS` / `EDITION_SELECT_WITH_SERIES` (zero extra DB queries). Precedence in `eventScale()`: User choice (`e.kind`) > Series kind (`e.seriesKind`) > Day/Act/Clashfinder rules.
  (3) Place Autofill in Global Archive: `ArchiveSeries`, `SeriesDetail` (when `kind === 'festival'`), and `EditionFactsForm` share `SuggestInput` (`Brand`, `City` via `/api/places/cities`) and `/api/places/guess` 1-tap `"Use ... from the map"` (`placePatch`) offers; `SeriesDetail` also offers `"Use ... from attached editions"` when series place is empty and attached editions agree.
  (4) Multi-Weekend Research & Draft Sibling Seed: `researchEditionFacts` (`details.ts` & `detailsGemini.ts`) extracts and preserves `Weekend 1` & `Weekend 2` date spans from Ticketmaster (non-contiguous runs), web results, and quoted Gemini page extraction (`details@2`), offering 1-tap `"Use Weekend 1 & Weekend 2 dates"` in Check details and `EditionFactsForm`. In `EditionFactsForm`, toggling `Multiple weekends` detects whether existing dates belong to W1 or W2, places them into the matching slot, and pre-fills the sibling weekend at `±7 days` as an editable draft (`"Draft (-7d) — confirm"` or `+7d`), requiring an owner `Source note` before saving (never auto-saved or used during background ingest).


- **ADR-007 (2026-11-18):** Series type fix (`docs/specs/series-type-fix.md`). `event_series.kind` may be empty (migration 0053) and is never defaulted to `festival`; the UI shows "Not set". Every series save is logged and undoable. This replaces the `not null, default 'festival'` part of ADR-006 (1).
- **ADR-008 (2026-11-26):** Shared artist genres (`docs/specs/canonical-genres.md`, approved by Charlie). Genres move from per-member to one shared set per artist, set only by the owner (new `owner` source on `artist_genres`) over music-story and MusicBrainz. Every write is one database function (`artist_genres_write`, migration 0059) that upserts and logs in one transaction to append-only `artist_genre_changes`; undo replaces the `genres_csv_undo` setting from the genres CSV design. The owner's export reads all members' seen acts only through the service-role-only `seen_act_names()` function (key and name, no member, event, date or count), not by widening the request-scoped store. Trade-offs: the owner gains an unattributed view of act names members saw (REQUIREMENTS.md Scope gets an exception, member notice to version 4); members can no longer change the shared genres but may add their own on top (Charlie's revision, same day): kept in `user_artist_genres` as source `added`, merged after the shared base by `genresByArtist` (deduped by style, each addition `1/(n+m)`, shared shares scaled by `n/(n+m)`), shown only to that member, never logged, exported or shared; members' old rows read as additions. Rejected: reading all `logged_events` with the system store (returns personal fields), a separate canonical genres table (duplicates `artist_genres` and its readers), and keeping the owner's `you` source (ambiguous with members' rows).
