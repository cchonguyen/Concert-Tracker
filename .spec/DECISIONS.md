# Architecture Decision Records (ADRs)

- **ADR-001 (2026-10-26):** Adopted the claude-harness-hub v2.0 harness (hooks, subagents, `.spec/` state). Engine files are copied unchanged from the hub so `/sync-harness` can update them; project rules stay in AGENTS.md and take precedence over the harness rules. `.spec/` files link to REQUIREMENTS.md and ARCHITECTURE.md rather than duplicating them. Rejected: replacing CLAUDE.md with the hub template (would drop the pointers to the project rules); copying the hub's `.spec/` files verbatim (they describe the hub, not this app).
- **ADR-002 (2026-10-28):** Manage section moves artists, people, venues, places, series and organizations to entity records with UUIDs. The Gemini audit returned APPROVED_WITH_REVISIONS, and all five blocking findings were checked against the code and applied to SYSTEM_SPEC.md section 3: kind-scoped alias uniqueness; `merged_into_id` with flattening, no hard delete and link constraints in both stores; dual-write of legacy text columns on rename, merge and venue → place during the 0014 release; reverse-patch manifests in `entity_history`; and venue provenance plus fillPatch-only list import. Its MVP "Do NOT Build" additions were taken as-is (no labels, single-name people, no delete), and its slice split was adopted as M1a–M6. Corrections to the verdict: tests run on Node's test runner (`npm test`), not vitest. `[UI / VISUAL]` slices still run `npm test` per AGENTS.md. `editPatch` exists only for rows from the app's own export or sheet (`src/services/listImport.ts`), so retiring it removes the read-back half of sheet sync, which matches Charlie's 2026-10-28 call that the app is the only source of truth. Already covered before the audit: one-way Sheets and CSV, and conflicts staying empty with a Data health ask.
- **ADR-003 (2026-11-13):** AI reader behind one provider-neutral interface, spec in docs/ai-reader-spec.md. (1) Two adapters (Gemini paid, model pinned by name; Workers AI via the `ai` binding), chosen by `READER_PROVIDER`, default `gemini`, no automatic fallback. Rejected: a fallback chain (breaks AGENTS.md quota rule) and a third provider before the test. (2) Spend guards and the circuit breaker keep their counters in `quota_ledger` keys, not in `ai_calls`, so a missing log table can neither block nor unblock calls, and every Worker instance shares them. Rejected: summing `ai_calls` per check (extra subrequests, couples safety to the log). (3) The log is one insert per call and stores counts only, never page text. (4) Over-size input is refused and logged, not chunked, in v1; the existing declared `lineupWindow` stays. (5) SUPERSEDED by ADR-004: the recall test was an owner-only route doing one provider and one page per request; it is now a local CLI script. (6) Invalid JSON is a failed read that drops the page with a log line; no repair call and no retry.
- **ADR-004 (2026-11-13):** Revisions to ADR-003 from Charlie's audit (2026-11-12), applied to docs/ai-reader-spec.md. (1) The recall test is a local CLI (`scripts/recall-test.ts`) over pure scoring in `src/server/reader/recall.ts`; no recall routes, no `run_id`, `names_expected` or `names_matched` columns, no `recall_test` feature, no `listAiCallsByRun` or `listRecallCandidates`, no React runner. The owner panel is observability only. Workers AI production slices (10.15, 10.16) are built only after Charlie reads the CLI result. Reason: a one-off evaluation does not earn permanent production surface. (2) Reasoning and parameters: `READER_THINKING_LEVEL` (default `LOW`); `thinkingBudget: 0` for `gemini-2.5*`, `thinkingLevel` for every other model; no sampling parameters; no trailing `model` turn; Workers AI `reasoning_effort` and `enable_thinking: false`; the empty-balance 402 or 429 maps to a 6 hour quota park. Reason: thinking tokens bill as output and can exhaust the output cap before JSON appears, and legacy parameters return 400. (3) Zero-deploy swaps: the unknown-price guard is removed; `FALLBACK_PRICES` (gemini 1.50/7.50, workers-ai 0.10/0.40 per million tokens) price unlisted models; only `-latest` aliases are refused, and only when `READER_PROVIDER` is explicit. (4) Breaker scope: guard 5 (input size) returns `input_too_large` for that page and guard 6 (job cap) parks only its job; neither touches `reader:breaker`. The breaker opens only on consecutive provider failures, provider 402/429, and guards 7 to 9. Reason: one big page must not stop every job. (5) Spend math: a pre-call in-memory check of `used + worstCase`, no ledger write before the call, one post-call write of the real cost. Reason: avoids double counting. The race note applies to non-queue callers only. (6) Defaults `READER_WINDOW_CHARS` 180000 and `READER_MAX_INPUT_CHARS` 200000 so a 43,000-token page is read whole; worst case per call is about $0.16 at the fallback price. (7) Model decision (Charlie): Gemini Hydrogen (`gemini-4-hydrogen`) is the wanted model, set only after the implementer confirms the id from the live model list and records the real price (slice 10.17); until then the code default stays `gemini-3.5-flash-lite`.
- **ADR-005 (2026-11-15):** Global Archive Merging, 4-tier Series/Brand Hierarchy, Multi-Weekend Pre-Fill, and Egress Cuts.
  (1) Nullable `event_editions.series_slug` (`ON DELETE SET NULL`) with removal of automatic stub `event_series` row creation for standalone concerts; standalone editions remain unattached to series.
  (2) 4-tier hierarchy `Brand -> Series -> Edition -> Event/Weekend`: add `brand` (text) and `aliases` (text[]) to `event_series`, `weekends` (`jsonb` array of `{ weekendNumber, name, startDate, endDate, ticketTypes?, lineupActs? }`) and `region` (text) to `event_editions`. Personal logged events link to edition + optional weekend index.
  (3) Option 3B fast-Enter auto-linking: typing an event line and pressing Enter directly auto-links if and only if exactly 1 verified series edition unambiguously matches without date/venue conflict; if 2+ editions match (e.g., multi-weekend or multi-city), auto-linking is suppressed and they are surfaced as 1-tap canonical candidates with a "None of these — search web / keep mine" escape hatch.
  (4) Supabase egress optimization: replace unbounded `event_editions` + `performances` payload scans with `getEditionHeaders` / `listEditionHeaders` (id, title, series_slug, dates, venue, city, region, act_count only) for `match.ts` and `dedupeProvisional.ts`; introduce `edition_lineup_facts` SQL RPC for single-roundtrip lineup retrieval; debounce Global Archive and edition suggestion client searches to >=300ms.
