# Architecture Decision Records (ADRs)

- **ADR-001 (2026-10-26):** Adopted the claude-harness-hub v2.0 harness (hooks, subagents, `.spec/` state). Engine files are copied unchanged from the hub so `/sync-harness` can update them; project rules stay in AGENTS.md and take precedence over the harness rules. `.spec/` files link to REQUIREMENTS.md and ARCHITECTURE.md rather than duplicating them. Rejected: replacing CLAUDE.md with the hub template (would drop the pointers to the project rules); copying the hub's `.spec/` files verbatim (they describe the hub, not this app).
- **ADR-002 (2026-10-28):** Manage section moves artists, people, venues, places, series and organizations to entity records with UUIDs. The Gemini audit returned APPROVED_WITH_REVISIONS, and all five blocking findings were checked against the code and applied to SYSTEM_SPEC.md section 3: kind-scoped alias uniqueness; `merged_into_id` with flattening, no hard delete and link constraints in both stores; dual-write of legacy text columns on rename, merge and venue → place during the 0014 release; reverse-patch manifests in `entity_history`; and venue provenance plus fillPatch-only list import. Its MVP "Do NOT Build" additions were taken as-is (no labels, single-name people, no delete), and its slice split was adopted as M1a–M6. Corrections to the verdict: tests run on Node's test runner (`npm test`), not vitest. `[UI / VISUAL]` slices still run `npm test` per AGENTS.md. `editPatch` exists only for rows from the app's own export or sheet (`src/services/listImport.ts`), so retiring it removes the read-back half of sheet sync, which matches Charlie's 2026-10-28 call that the app is the only source of truth. Already covered before the audit: one-way Sheets and CSV, and conflicts staying empty with a Data health ask.
- **ADR-003 (2026-11-13):** AI reader behind one provider-neutral interface, spec in docs/ai-reader-spec.md. (1) Two adapters (Gemini paid, model pinned by name; Workers AI via the `ai` binding), chosen by `READER_PROVIDER`, default `gemini`, no automatic fallback. Rejected: a fallback chain (breaks AGENTS.md quota rule) and a third provider before the test. (2) Spend guards and the circuit breaker keep their counters in `quota_ledger` keys, not in `ai_calls`, so a missing log table can neither block nor unblock calls, and every Worker instance shares them. Rejected: summing `ai_calls` per check (extra subrequests, couples safety to the log). (3) The log is one insert per call and stores counts only, never page text. (4) Over-size input is refused and logged, not chunked, in v1; the existing declared `lineupWindow` stays. (5) The recall test is an owner-only route doing one provider and one page per request, because the AI binding and Gemini key exist only in the Worker and a request is limited to 50 subrequests. Rejected: a container script. (6) Invalid JSON is a failed read that drops the page with a log line; no repair call and no retry.
